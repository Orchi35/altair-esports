# Builder sharing and PNG cards

The toolbar publishes a validated, immutable build snapshot without requiring an account. `POST /api/builds` accepts `{build}` and returns a 12-character content-derived ID. The public URL is `/b/<id>`; a Vercel rewrite serves the builder, which loads the record with `GET /api/builds?id=<id>`. A language switch preserves the ID as `/en/builder#b=<id>` or `/tr/builder#b=<id>`. Existing `#build=` JSON links remain supported. Edits clear the displayed share link; publishing again creates a new snapshot instead of changing the old one. Identical normalized snapshots reuse an ID. Hash collisions are checked against the full record and cannot overwrite it.

Live storage uses `BUILDER_REDIS_REST_URL` and `BUILDER_REDIS_REST_TOKEN`, or the existing complete `PENALTY_REDIS_REST_URL`/`PENALTY_REDIS_REST_TOKEN` pair. Build records use only `altair:builder:v1:` keys, without expiry. No leaderboard or player ownership records are modified. A partial dedicated configuration fails closed. All credentials remain server-side. The rate-key HMAC secret can be set with `BUILDER_RATE_SECRET`; otherwise the penalty signing secret or Redis token is used. API reads and writes have ordered per-IP and global limits, creation is capped at 20/hour/IP and 200/day globally, and request bodies are limited to 16 KB. Repeated/idempotent submissions count toward these limits. Store unavailability is an explicit error, with a classic self-contained link available as a user-selected fallback.

Anyone with the link can read the build name, selections and notes. There is no private sharing or edit/delete account. Unlisted short routes have a noindex response header. Creation quotas protect resource use, not human identity. Build validation is versioned by the existing v3 schema; future calculator changes must preserve compatibility or provide a migration rather than silently discarding stored builds.

In **Vite development only**, if no Redis configuration exists, records are saved to `work/builder-shares.local` (gitignored). This local adapter is persistent across restarts, serializes writes and uses atomic file replacement. Corrupt files produce an error instead of being overwritten. It is never imported by the production API. Links on `127.0.0.1` work only on that machine, and local records are not transferred to production. Configured development Redis must be an isolated test store, not production.

`Build kartını indir` renders a 1600px-wide PNG with height determined by content. It includes the archetype, body, level, AP allocation, category ratings, every available attribute (base and all-bonus game value), styles, specialization, perks, facilities, budget, AI option, mastery settings and wrapped notes. The all-bonus values are explicit and independent of the on-page display toggle. Same-origin icons have a timeout and text fallback. Export is generated locally and does not depend on the sharing API; an existing short share URL is included when available. It is a factual build report, not an AI-generated image.

Checks: `npm run verify`, `node --test test/e2e/builder-sharing.e2e.test.js`. The browser test uses an isolated service fixture, never production storage, and writes a PNG to `work/builder-qa/build-card-tr.png` for visual review.
